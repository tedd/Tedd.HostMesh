Routing

How a stream survives a relay change

Authenticate the neighbors

Each agent pins member certificates and exchanges signed link-state updates. Both neighbors must report a link before other agents route through it.

Select a path

The default route maximizes bottleneck capacity. Latency routing uses accumulated delay and configured link costs. Only members granted the relay role forward transit traffic.

Keep the endpoints

The two endpoint agents own the inner QUIC connection. An alternate route can carry its outstanding bytes if connectivity returns before the transport times out.

Integration

Choose how your service connects

Existing TCP and UDP services
Bind an ingress socket and forward its traffic to a mesh address. The target agent connects to the backend. UDP preserves packet boundaries.
.NET applications
Use LocalMeshClient to open streams, listen on a mesh port, or exchange datagrams over an authenticated local socket.
ASP.NET Core and HTTP
Bind Kestrel to a MeshHttpEndPoint. For outbound requests, give HttpClient the handler from CreateHttpHandler().

Getting started

Run a two-agent mesh

Build with the .NET 10 SDK or later and a .NET 10 runtime with MsQuic support. The loopback guide uses PowerShell 7 and a Python 3 HTTP server.

Open the quickstart ↗

Build from source

git clone https://github.com/tedd/Tedd.HostMesh.git
cd Tedd.HostMesh
dotnet build Tedd.HostMesh.slnx

Then generate the two node identities and start Edge and Service using the example configurations.
